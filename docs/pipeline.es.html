Alkosto · Yalo · Agent Studio

Pipeline Alkosto–Algolia

Cómo el catálogo de Alkosto llega, dos veces al día y sin intervención manual, a los índices de Algolia que usan el bot de Yalo y los agentes de Agent Studio. Qué hay en cada pieza, cómo se monitorea, cómo se extiende y qué hacer cuando algo falla. ¿Nuevo en el proyecto? Empieza por la sección 12. La versión canónica de este documento es docs/pipeline.es.md en el repositorio.

Repositorio Wunderbot-Git/alkosto-yalo-feed App Algolia QX5IPS1B1Q (región US) Responsable Philipp Hasskamp Versión 2 de septiembre de 2026

1. Resumen

Alkosto publica un CSV con todo su catálogo (~11.800 productos, ~920 columnas). Un workflow de GitHub Actions lo descarga, se queda con las categorías relevantes, limpia y enriquece cada producto, y publica varios archivos JSON en el repositorio. Algolia lee esos JSON por HTTP con connectors y reconstruye cada índice. Nadie ejecuta nada a mano.

Alkosto
fuente
CSV completo del catálogo, protegido con Basic Auth. Se actualiza en las horas de la mañana y del mediodía.
GitHub Actions
6:45 · 12:45 Bogotá
Descarga, filtra por categoría, limpia, deriva campos, reescribe imágenes al CDN y genera un JSON por índice.
Repositorio
commit automático
Los JSON se guardan en main solo si cambiaron. Cada commit es una foto auditable del catálogo.
Connectors
8:00 · 14:00 Bogotá
Algolia descarga cada JSON desde su URL pública y hace full reindexing: borra y vuelve a cargar el índice.
Consumidores
búsqueda
El bot de Yalo (WhatsApp) consulta el índice principal; los agentes de Agent Studio consultan un índice por vertical.

Qué se automatizó

  • Descarga y filtrado del feed
  • Limpieza (NaN, columnas vacías, ceros iniciales en EAN)
  • Campos derivados: tipo de producto, % descuento, precios por medio de pago, pulgadas de pantalla
  • URLs de imagen al CDN estático
  • Un JSON por índice de Agent Studio
  • Recarga de todos los índices en Algolia

Qué sigue siendo manual

  • Crear un connector nuevo en Algolia cuando se agrega un índice
  • Cambiar la configuración de relevancia (reglas, sinónimos) — por API o en el dashboard
  • Renovar credenciales si Alkosto las cambia

2.4 Los connectors de Algolia

Un connector es la pareja source (la URL del JSON) + destination (el índice) + task (cuándo y cómo). Todos usan el conector de tipo JSON, autenticación None (la URL es pública), sin transformación, y la estrategia Full reindexing: cada corrida reconstruye el índice completo, así los productos que desaparecen del feed también desaparecen del índice. Se administran en Algolia → Connectors; el historial de corridas está en Connector Debugger.

3. El ciclo diario

Dos ciclos idénticos al día. Los horarios están escalonados a propósito: GitHub Actions no arranca puntual (su cola suele retrasar los jobs programados entre 30 y 50 minutos), y el JSON tarda hasta 5 minutos más en refrescarse en el CDN. El connector se programa 75 minutos después para leer siempre datos frescos.

  • 06:45 11:45 UTCSe programa el workflow de GitHub Actions. Alkosto ya publicó el CSV de la mañana.
  • ≈ 07:00 – 07:35 delay típico de GitHubEl job arranca de verdad. Tarda ~30 s: descarga, procesa, hace commit y push si algo cambió.
  • 08:00 13:00 UTCLos connectors de Algolia leen los JSON y reconstruyen los índices. Tarda entre 30 s y 5 min por índice.
  • 12:45 17:45 UTCSegundo workflow del día.
  • 14:00 19:00 UTCSegunda recarga de índices. A partir de aquí los precios de la tarde están en producción.

Por qué importa el escalonamiento. En agosto de 2026 el connector estaba programado solo 20 minutos después del workflow; como GitHub arrancaba 40 minutos tarde, el connector leía el JSON del día anterior y el bot mostró precios viejos hasta la corrida de la tarde. Si algún día vuelve a pasar, el síntoma es exactamente ese: índice al día por la tarde, desactualizado por la mañana.

Crons tal como están escritos (siempre en UTC):

# GitHub Actions — .github/workflows/feed.yml
45 11 * * *     # 06:45 Bogotá
45 17 * * *     # 12:45 Bogotá

# Todos los connectors de Algolia
0 13,19 * * *   # 08:00 y 14:00 Bogotá

4.1 Los dos formatos de registro

Crudo enriquecido

Las columnas originales de Alkosto en español (Título, Marca, Memoria RAM…) más los campos derivados del §5. El identificador único es Identificador del producto.

{ "Identificador del producto": "8806097665427",
  "Título": "Celular SAMSUNG S25 256GB 5G…",
  "Memoria RAM": "12 GB",
  "tipo_producto": "celular",
  "descuento_porcentaje": 56, … }

Schema limpio (solo computadores)

Campos en inglés, cada spec dos veces: valor numérico para filtrar y etiqueta para mostrar. Sin campos interpretativos. El identificador único es objectID.

{ "objectID": "195950715095",
  "name": "MacBook Pro 16\" …",
  "category": "laptop",
  "ram_gb": 48, "ram_label": "48 GB",
  "screen_inches": 16.2, … }

Al crear un connector, el campo Unique property identifier debe ser Identificador del producto para los índices crudos y objectID para agent_studio_computadores. Si se pone el equivocado, Algolia rechaza la fuente.

5. Qué trae cada registro

Además de las columnas de Alkosto, el pipeline agrega campos calculados. Están pensados para que el bot y los agentes filtren con precisión sin depender de reglas frágiles.

CampoTipoCómo se calculaPara qué sirve
tipo_productotextoPor prefijo de la ruta de categoría (mapa en process_alkosto_products.py). Ej.: TV>Smart TV> → televisor. Una marca nueva de TV entra sola.Filtro por tipo; destino de las reglas de Algolia; recortes por índice.
descuento_porcentajeentero(lista − venta) / lista × 100, truncado (56,52 → 56). Igual que alkosto.com.Filtros «más del 30 %», ranking de ofertas.
precio_<medio>enteroDel campo Precio por método de pago (codensa:2518070;tarjeta_alkosto:2498070). Un campo por medio: precio_codensa, precio_tarjeta_alkosto… Medios nuevos aparecen solos.Precio con tarjeta específica, filtros numéricos.
metodos_pagolistaLos medios detectados en el campo anterior.Facet «qué medios tiene este producto».
screen_size_inchesnúmeroBusca «Pulgadas» en Tamaño Pantalla_2 (monitores, TV) y luego en Tamaño Pantalla_1 (el resto). Si solo hay centímetros, convierte.Filtros de tamaño: screen_size_inches >= 27.
Enlace link1 / link2URLReescritas al CDN: …/products/<EAN>/<EAN>-001.webp.Imagen estable, sin depender del enlace del feed.

5.1 Limpieza aplicada a todos

  • Se eliminan las columnas totalmente vacías (de ~920 quedan ~110) y, por producto, los atributos vacíos o NaN. Un registro trae solo lo que tiene (27–57 atributos).
  • El EAN se lee como texto para conservar ceros iniciales. Antes pandas lo convertía a número y 010343958098 se volvía 10343958098, rompiendo el objectID y la URL de imagen.
  • Categorías excluidas explícitamente: ninguna hoy (la lista EXCLUDED_SUBCATEGORIES está vacía). La categoría Smartwatch> está mapeada pero Alkosto no la incluye actualmente en el feed.

6. Configuración en Algolia

La configuración se aplica por API desde scripts, no a mano, para que sea reproducible. Lo que hay en cada índice:

6.1 Común a todos

  • Idioma español: queryLanguages, removeStopWords e ignorePlurals en ["es"]. Algolia ignora «el/la/de/para» y entiende plurales sin listas hechas a mano.
  • Sinónimos: 44 grupos compartidos (portátil↔laptop↔notebook, nevera↔refrigerador, airfryer↔freidora de aire, mouse↔ratón, powerbank↔batería externa…).
  • Filtros numéricos: cualquier campo numérico (Precio de venta, descuento_porcentaje, screen_size_inches…) se puede filtrar sin configuración adicional.

6.2 Índice principal de Yalo

  • Atributos buscables: 21, en orden de prioridad: Título, Marca, Categoría, características clave, procesador, RAM, disco, pantalla, sistema operativo…
  • Facets: Categoría, Marca, Memoria RAM, metodos_pago, tipo_producto (todos filterOnly).
  • Reglas: ~47. Cada una convierte una palabra de la consulta en un filtro de tipo: «portátil» → tipo_producto:laptop, «nevera» → nevera, «refrigerador» → nevera OR nevecon, «airfryer» → freidora_aire… Así «monitor 27» no devuelve laptops con pantalla de 27.
  • Ranking personalizado: desc(Disponibilidad) — a igual relevancia, primero lo que tiene más stock.

6.3 Índices de Agent Studio

Los agentes reciben cada producto completo en su contexto, así que aquí el criterio es menos es más:

  • attributesToRetrieve recortado: el agente ve entre 17 y 55 atributos elegidos para su vertical (RAM, cámaras y batería en celulares; pulgadas, resolución y HDMI en TV; litros, kilos, BTU y eficiencia en electrodomésticos), no las 100 columnas del feed. La lista vive en agent_indices.json.
  • Facets por vertical: tipo_producto y Marca con conteos, más los filtros propios de cada categoría.
  • Reglas solo de su vertical: el índice de TV tiene las de televisor, barra de sonido y proyector; el de electrodomésticos, las 15 de neveras, lavadoras, estufas, etc. Una regla ajena en un índice pequeño devolvería cero resultados.
  • Ranking: desc(Disponibilidad), desc(descuento_porcentaje). En computadores: desc(stock), desc(discount_pct).

Comportamiento esperado, no error: buscar «celular» en el índice de electrodomésticos devuelve neveras Samsung, porque su descripción dice «contrólala desde tu celular». Es coincidencia de texto; el índice no contiene celulares. Los agentes deben filtrar por tipo_producto, no confiar solo en la palabra.

6.4 Configuración como código

La configuración de cada índice productivo está en el repositorio, en algolia/<índice>/, y se mueve con dos scripts:

cp .env.example .env                                   # llenar las llaves
python scripts/export_algolia_config.py                # dashboard → repo, todos los índices
python scripts/apply_algolia_config.py agent_studio_tv # repo → índice
python scripts/apply_algolia_config.py agent_studio_audio --load agent_studio_audio.json   # índice nuevo

Regla: un cambio se hace en el repo y se aplica, o se hace en el dashboard y se exporta — pero siempre termina en un commit. Así nunca hay dos versiones de la verdad, y cualquier índice se puede recrear desde cero.

7. Cómo extender

Las tres operaciones habituales. Todas empiezan por un cambio en el repositorio; el workflow hace el resto en la siguiente corrida (o de inmediato con Run workflow en la pestaña Actions).

7.1 Agregar una categoría al índice principal

  1. Ubicar la ruta exacta en el CSV (el log del workflow lista todas las subcategorías detectadas).
  2. En process_alkosto_products.py, agregar el prefijo a CATEGORY_PREFIXES y una línea por subcategoría en TIPO_PRODUCTO_PREFIXES, por ejemplo ("Electrodomésticos>Lavado>Secadoras", "secadora"). Las rutas más específicas van antes que las genéricas.
  3. Commit y push. Verificar en el JSON publicado que el nuevo tipo_producto aparece con la cantidad esperada y que no quedan productos sin tipo.
  4. En Algolia, agregar una regla «palabra → tipo_producto:nuevo» y los sinónimos coloquiales.

7.2 Agregar un índice de Agent Studio

  1. Agregar una entrada en agent_indices.json con el nombre (prefijo agent_studio_), los tipos que entran y los atributos que el agente debe ver.
  2. Commit y push. El workflow genera agent_studio_<nombre>.json.
  3. Crear la carpeta algolia/<índice>/ copiando la de un índice hermano y ajustar; luego scripts/apply_algolia_config.py <índice> --load <archivo>.json crea el índice con su configuración y su primera carga.
  4. Crear el connector en Algolia → Connectors → JSON: URL del archivo, identificador Identificador del producto (o objectID si usa schema limpio), Create one for me en credenciales, cron 0 13,19 * * *, full reindexing.

Candidatos ya definidos y pendientes de crear: audio, pequeños electrodomésticos, videojuegos, casa inteligente + cámaras, accesorios.

7.3 Agregar un campo derivado

Se calcula en convert_to_json de process_alkosto_products.py, dentro del bucle por registro, antes de la limpieza de vacíos. Regla de oro del proyecto: el índice guarda hechos, no interpretaciones. Sí: pulgadas, litros, porcentaje. No: «ideal para gaming», «nivel de uso». Eso lo decide el agente con su prompt.

8.3 Forzar una actualización ahora

  1. Actions → Refresh Alkosto product feed → Run workflow. Esperar el commit (~1 min).
  2. Esperar 5 minutos más (caché del CDN) antes de tocar Algolia; si no, el connector lee la versión anterior.
  3. Connectors → la tarea del índice → Run. Verificar en Connector Debugger que ingirió el número de registros esperado.

10. Decisiones de diseño

GitHub Actions en lugar de un servidor propio

Gratis para repositorios públicos, sin infraestructura que mantener, cada corrida queda versionada y el mismo repositorio sirve como hosting de los JSON. La alternativa (un cron en un Mac) dependía de que el equipo estuviera encendido.

Transformar en Python, no en Algolia

Algolia ofrece «transformations» en el connector. Se descartó: la lógica ya existía en Python, es testeable localmente y queda versionada; repartirla en dos sistemas la haría inmantenible.

Filtrar por prefijo de categoría, no por lista de rutas

Una lista de rutas exactas se rompe cada vez que Alkosto agrega una marca. Con prefijos (TV>Smart TV>) las marcas nuevas entran solas. Lo mismo para medios de pago.

tipo_producto como pieza central

Las reglas de Algolia enumeraban rutas de categoría por marca. Un campo estable por tipo convierte cada regla en una línea y desacopla al bot de la taxonomía de Alkosto.

Un índice por agente, derivado del feed principal

Los agentes de Agent Studio meten cada resultado en el contexto del modelo. Índices pequeños y con pocos atributos dan mejores respuestas. Derivarlos del feed principal evita mantener pipelines paralelos, que ya demostraron desviarse (el de celulares perdió una marca).

Hechos, no interpretaciones

El índice no guarda campos como «para gaming» o «nivel de uso». Son juicios que cambian y que el agente hace mejor con su prompt sobre datos objetivos (GPU dedicada, RAM, peso).

11. Glosario

Connector
Integración de Algolia que trae datos de una fuente externa a un índice según un cron.
Full reindexing
Estrategia del connector: reconstruye el índice completo en cada corrida. Elimina lo que ya no está en la fuente.
objectID
Identificador único de un registro en Algolia. Aquí siempre es el EAN.
Facet
Atributo declarado para filtrar (y opcionalmente contar). Un filtro sobre un atributo no declarado se ignora en silencio.
Rule
Regla de Algolia: si la consulta contiene X, aplica el filtro Y. Aquí: palabra → tipo_producto.
attributesToRetrieve
Lista de atributos que Algolia devuelve por resultado. Recortarla es lo que controla cuánta información recibe un agente.
Raw URL
URL pública de un archivo en GitHub (raw.githubusercontent.com). Caché de 5 minutos.
Agent Studio
Producto de Algolia para construir agentes conversacionales que consultan índices como herramientas.

12.3 Correr el pipeline en local

Útil para probar un cambio de categorías antes de hacer push.

ALKOSTO_USERNAME=… ALKOSTO_PASSWORD=… python process_alkosto_products.py   # descarga productFeed.csv
python process_alkosto_products.py --skip-download                          # reutiliza el CSV ya descargado
python replace_image_urls.py filtered_products.json
python build_agent_indices.py --input filtered_products.json --config agent_indices.json

El CSV (~32 MB) y los filtered_*.csv están ignorados por git; solo los JSON se commitean, y eso lo hace el workflow.

12.4 Qué leer, en qué orden

§1 (qué es) → §3 (cuándo pasa) → §4–5 (qué hay en los índices) → §8 (qué mirar cuando algo falla). El README del repositorio tiene el detalle técnico. Antes del primer cambio: todo ajuste de relevancia en Algolia termina en un commit (§6.4); todo cambio de categorías se verifica en el JSON publicado antes de tocar Algolia (§7).
